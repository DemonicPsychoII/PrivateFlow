# Private Flow development

Windows only. This is a personal app published as is. No telemetry or silent cloud fallback; audio and speech recognition stay local. Per the owner's request (2026-10-04), the opt-in Concise output style may send transcript text (never audio) to the configured OpenAI-compatible API; it must stay off unless selected and fall back to on-device Clean on failure. Per the owner's request (2026-11-16), model-written meeting notes may send the transcript text of one meeting (never audio) to the same API, only when the user presses the button for that meeting; they fall back to the extractive notes, with the reason shown, on failure. Notes by the local model send nothing anywhere. Do not commit audio, model weights, settings, transcripts, credentials, or generated packages.

Preserve cancellation and insertion safety: session IDs reject stale results, the paste goes only to the window selected at recording start, password fields and Private Flow itself never receive a paste, modifiers block insertion, and no Enter virtual key is sent. Per the owner's request (2026-10-04), insertion pastes into any other field via clipboard and Ctrl+V, excludes the text from clipboard history and restores the previous clipboard; when it cannot paste, it leaves the text on the clipboard and notifies instead of opening the window. Per the owner's explicit request, automatic insertion is on by default; migrate the old default once and preserve later explicit opt-outs. The configurable shortcut toggles recording by default; per the owner's request (2026-11-16), hold to talk is an opt-in setting that records while the shortcut is held, discards a tap under about 0.3 s and waits, bounded, for the held modifiers to be released before the existing modifier rule applies. Per the owner's request (2026-11-16), an optional meeting shortcut, not set by default, starts and stops meeting capture without showing the window; the meeting pill and the tray recording state show the capture for as long as it runs. Per the owner's request (2026-11-17), a Local polish dictation that arrives while meeting notes are written on this PC waits for them, for at most the time set by the user (two minutes by default) and then uses Clean; after such a wait the text is pasted only if its window is still in front by itself, and otherwise the notice is shown and the clipboard is left untouched. Never use a user's microphone or send keyboard input to their existing apps for tests without an explicit user gesture; use synthetic audio and isolated test fixtures.

Use `scripts/build.ps1 -Portable` for build and safety verification. Use `scripts/smoke-test.ps1` for a real-engine synthetic-speech check after setup. Report unverified behavior plainly. Keep runtime dependencies and model downloads pinned and hash-verified. Native speech model execution and audio handling remain local. Per the owner's request (2026-11-17), releases are versioned 0.5.n as internal betas: every pull request that changes the app raises the last number in the project version and heads its release notes with that version; the build check keeps the two in step.

Plans and validation live in docs. No mobile/Mac work unless the owner changes scope.

The internal repository's CI uses its existing self-hosted runner, with no hosted fallback.
Public snapshots are produced by `scripts/export-public.ps1` and carry no workflows.
